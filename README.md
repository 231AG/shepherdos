# Church Connect demo

A clickable, front-end-only demo of **Church Connect**, a multi-church management platform for Liberian churches: members, Sunday check-in that works offline, LRD and USD giving, and SMS.

Everything runs in the browser on fictional, generated data. There is no backend, no real sign-in and no real SMS. It is a static export hosted on Vercel.

> Status: **Phase 3 of 6**. Done: foundation, demo sign-in, role and church switching, dashboard, members (directory, profile, add/edit, notebook import), attendance (services, offline Sunday check-in, trends), giving (capture, append-only ledger, reversals, offline drafts, daily close, CSV export) and the platform console with read-only support sessions. Modules from later phases show a short "arrives in phase N" screen.

## Run it locally

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # static export into ./out
npm run serve        # serves ./out on http://localhost:4173
npm run lint
```

Requires Node 20+.

## How the mock data layer works

```
src/mock/seed.ts     generates the demo data (only the repository imports it)
src/mock/prng.ts     seeded random numbers + stable UUIDs (uuidFrom("member:grace:17"))
src/data/types.ts    domain types shaped like the spec's data model
src/data/store.ts    zustand store, persisted to localStorage (versioned)
src/data/repo.ts     the repository: every read and write goes through here
src/data/core.ts     seed + delta merge and write helpers (used only by repository modules)
src/data/members.ts, attendance.ts, importer.ts, giving.ts   repository modules, re-exported by repo.ts
```

- **Generated relative to today.** The seed is rebuilt on every page load from the current date, so "last 12 Sundays" are always the most recent 12 Sundays and nothing looks stale.
- **Deterministic.** A seeded PRNG makes the data identical on every load and every reset.
- **Stable ids.** Records get UUIDs derived from a fixed key, so a member keeps the same id from day to day.
- **Visitor changes are deltas.** Only what the visitor adds or changes is saved (`added` rows and `patched` fields per table) under the `shepherdos-demo` localStorage key. "Reset demo data" clears the deltas. If storage is unavailable (private browsing), the store falls back to memory.
- **Spec rules are kept even in the demo.** Every church-owned row has `church_id`; money is integer minor units plus `LRD` or `USD` and is never summed across currencies; the giving ledger is append-only with linked reversal rows; member status (New / Active / Inactive / Excused) is derived from attendance and the church's thresholds, never stored.
- **Roles.** `src/lib/access.ts` holds the role matrix (which modules each role can open, ledger visibility, contact masking). Department heads are scoped to their department through `getScope()` in the repository.

### The sample notebook file

`public/samples/members_notebook.csv` is the messy spreadsheet behind "Use sample notebook file" in the import wizard: mixed 077 / 0886 / +231 phone formats, blank lines, 3 possible duplicates of Grace Fellowship members and 11 rows that need fixing. It is generated by `npx tsx scripts/generate-sample-csv.ts`, which also runs the real review logic and fails unless the file produces exactly 198 ready, 3 duplicates, 11 errors and 187 normalised phones.

### Offline check-in (simulated)

The Online/Offline switch in the header simulates the network. Offline check-ins are saved with a `pending` state; going back online (or "Sync now") replays the queue and marks them `synced`. Grace Fellowship's open Sunday service is seeded mid-service: most regulars are in, two check-ins wait on the device and one (Felix Massaquoi) failed, to show Retry. Imported members show as New until their first check-in, so an import never marks people inactive.

### Giving rules (enforced in `src/data/giving.ts`)

- Posted entries are never edited or deleted. A correction is a separate reversal row (`REV-…`) linked to the original, with a required reason; the original stays visible as "Posted · reversed". An entry can be reversed once.
- Offline captures are drafts (`DR-…`). They never count in posted totals and wait for treasurer review (post or discard). A draft that matches a posted entry (same member, amount and currency within 10 minutes) is flagged as a possible duplicate, never merged automatically.
- A day can't be closed while drafts for it are pending; once closed, nothing more can be posted or reversed for it.
- LRD and USD are totalled separately everywhere. Pastors see totals only, the full ledger, or nothing, per the church setting.

### Support sessions (simulated)

A platform operator can only open a church's records under an approved, time-limited grant. In the Platform console, "Open church" starts a read-only session (dashboard, members without phone numbers, attendance; never giving) with a countdown bar. When the grant expires the session ends by itself. Requests for access appear on the church pastor's dashboard to approve or deny. Every step writes an audit event.

### What the full version replaces

Only the repository modules in `src/data/` (and `src/data/store.ts` for local UI state) change. Queries become Supabase reads under row-level security; commands (`logFollowUpNote`, `syncNow`, later `checkIn`, `postGiving`, `reverseGiving`) become server actions or Postgres RPCs; the offline queue moves to IndexedDB behind a service worker. Components keep calling the same functions. `src/mock/` is deleted.

## Swapping the logo

The logo is drawn in one component: `src/components/brand/Logo.tsx` (`BRAND_NAME`, `LogoMark`, `Logo`). The mark image is `public/brand/church-connect-mark-160.png` (UI) and `public/brand/church-connect-mark.png` (512 px, used for icons), both cut from the supplied logo with a transparent background. The full logo with wordmark is `public/brand/church-connect-logo.png`.

1. Replace the PNGs in `public/brand/` (keep them square with a transparent background), and change `BRAND_NAME` if the name changes.
2. Regenerate the favicon and app icons:
   ```bash
   npm run build
   npm run serve        # leave running
   npm run icons        # writes public/icons/* and public/favicon.ico
   ```
   The script screenshots the hidden `/brand-preview/` page, which renders `LogoMark`.
3. Refresh the landing page screenshot with `npm run shots:landing`, then rebuild.

## Design tokens

Colours, fonts and shadows are Tailwind theme tokens in `src/app/globals.css`. The default Tailwind palette is removed, so components can only use the Church Connect tokens. Teal text and white-on-teal buttons use `teal-ink` (#0E6B63) for WCAG AA contrast; `teal` (#16877E) is for fills, icons and charts.

## Deploying (Vercel)

Import the GitHub repository in Vercel with the **Next.js** framework preset and default settings: build command `npm run build`. Because `next.config.ts` sets `output: "export"`, Vercel serves the generated `out` folder as static files. `trailingSlash: true` emits `/members/index.html`-style files, so clean URLs work without extra rewrites. Every push to `main` deploys to production; pull requests get preview URLs.
